# Laravel Activity Matrix

`ActivitySanitizer::details` accepts server-owned `maxBytes`, `maxStringLength`, `maxDepth` and `maxItems` (per array) for authorized lazy source-detail projections. Defaults remain16384 bytes,512 characters, depth5 and100 items per array for recording/jobs. A host may use a larger bounded display budget without weakening redaction or copying payloads into activity entries. These parameters must never come from request input.

Generic queued append-only activity projection, bounded details, JSON DTOs and keyset queries. Laravel 13 / PHP 8.4. No application classes, auth rules, routes or frontend dependencies.

`ActivityQuery::feedQuery(Builder $query, array $filters)` lets a trusted host supply an already authorized, scope-constrained ActivityEntry query with domain-specific membership rules. The same rules then apply before keyset pagination, `has_more` and `pending_count`. The host owns scope authorization and correlation semantics; the package neither infers domain identity nor loads detail payloads into feed responses.

For domain fields incorrectly classified by the generic key mask, a trusted host may pass `visiblePaths` as exact arrays of key segments (`'*'` represents numeric indices), for example `[['request', 'items', '*', 'content']]`. This exempts only that key at that path: child keys, embedded credentials, JSON budgets and text bounds remain sanitized. Keep this allowlist server-owned and confined to authorized lazy details; default recording/feed behavior has no exemptions.

Register through Composer discovery and apply the additive migration. The host authorizes a scope and calls `ActivityRecorder::record(scope, eventKey, metadata, details)` inside the source transaction. This captures an immutable sanitized snapshot and timestamp, then registers a `DB::afterCommit` callback to dispatch `RecordActivity` to a durable database queue. No queue SQL runs before source commit; rollback discards the callback. Without an active transaction the callback runs immediately. The callback uses a separate enqueue transaction; `beforeCommit()` applies only to that enqueue transaction and overrides queue-level after_commit settings for this job only. It does not insert activity rows or acquire projection locks in the source flow. The API returns void.

Configure `activity-matrix.connection` and `activity-matrix.queue` to an existing durable worker connection and queue. The connection defaults to `queue.default`, the queue to `default`. This primitive requires Laravel DatabaseQueue with the exact same database Connection object as the default source/projection connection. Other drivers and different database connection objects are rejected with a bounded failure event, even if two connections name the same database. There is no silent fallback or global queue setting change. The host owns worker operation and restarts after code changes. Recording is eventual.

Only the job writes entries. It takes a per-scope lock within its own transaction, without source-domain locks, so committed projection IDs are safe keyset cursors. IDs express projection insertion order; source `occurred_at` remains the original captured time even when workers complete out of order. Stable hashed scope/event keys make retries duplicate-safe; five attempts use backoff 1/5/15/60 seconds. Jobs serialize bounded metadata and details, never Eloquent models or source payloads. A source advancing or disappearing before execution cannot change the captured transition.

Enqueue SQL failures roll back the separate enqueue transaction and emit a bounded failure event after the source has committed. Monitoring is fail-open: queue failure cannot undo or poison the source transaction. `ActivityRecordingFailed` reports only a stage and bounded exception class; hosts attach their own safe diagnostics. There is an explicitly accepted source-commit/enqueue crash window: process death or queue failure can leave a missing projection. There is no automatic outbox, reconstruction or backfill and no no-loss guarantee. Source journals remain authoritative; the projection is not an audit guarantee.

Metadata requires operation/category/status/summary; actor_id/actor_label/correlation_id/occurred_at are optional. Never submit raw requests, commands, provider content or credentials. Details encode to at most 16384 JSON bytes including escaped Unicode, control characters, keys and redacted values. Limits are 100 input items per array, depth5, strings512 characters and keys80 characters; any loss sets root `_truncated: true`. Redaction alone does not mark truncation. Feeds exclude details in SQL.

Sensitivity detection uses original keys before shortening. Collisions preserve the first key and mark loss; malformed display UTF-8 is repaired. Scope and nullable actor/correlation references must be safe UTF-8 of at most100 characters; invalid identities are rejected instead of silently shortened. String defenses cover recognized embedded credential assignments, encoded query parameter names, Basic/Bearer credentials and URI userinfo. These defenses supplement the host's semantic allowlist.

`ActivityQuery::feed(scope, filters)` accepts agent, operation, from/to, before/after, independent since, and limit1..500 (default240). Results contain descending bigint-string IDs, older/newer cursors, has_more and pending_count. The latter counts rows after since with identical filters, independently of pagination; it is zero without since. `after` selects the nearest ascending page before reversing presentation. Continue from newer_cursor while has_more. No offsets or whole-history hydration. `detail(scope,id)` preserves exact scope. Trusted host aggregate readers may instead call `feedScopePrefix(prefix, filters)` / `detailScopePrefix(prefix,id)`; `feedLatestCorrelatedScopePrefix(prefix, filters)` additionally keeps only the highest ID per `scope + category + operation + correlation_id` while retaining every row whose correlation is null. Collapse precedes keyset/pending-count filters. The prefix must be non-empty, at most100 bytes and literal (no `%`, `_` or backslash), so a host can authorize a bounded cross-scope projection without exposing SQL wildcard semantics.

`ActivityRecorded(scope,id)` emits after worker commit and only for newly inserted entries. Subscriber/admission errors are reported as bounded invalidation_enqueue failure events without undoing the committed projection. Hosts attach private-channel coalesced invalidation, with no detail payload broadcasts. Socket/diagnostic failures must not change committed outcomes.

Entries are compact persisted read projections; DTOs are their transport shape. Hosts retain source correlations and lazily resolve associated diagnostics and frozen flow definitions under their own authorization. The Local GPT adapter copies only semantic lifecycle/tool/Overseer metadata and API method/endpoint/status/duration/request ID; it copies no request/response bodies, messages, command output or procedure graphs. It uses the existing managed database queue/default queue. Its app invalidation listener is itself queued after commit; only that second job broadcasts/coalesces, carrying scope/id without details. No retention deletion, source-history backfill, process startup or migration reset occurs automatically.

The host test suite covers guarded PostgreSQL transactions, real durable enqueue and actual Laravel job pop/fire, same-connection enforcement, independent-reader visibility, nested/source rollback, SQL failure isolation, retry idempotence, historical snapshots, sanitized bounds, scoped queries and private invalidation. Independent finite two-process probes verify source lock inversion removal and worker commit/rollback visibility. They do not assert absence of every possible domain deadlock.
